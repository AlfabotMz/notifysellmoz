# PROMPT COMPLETO: Plataforma de Automação Shopify + WhatsApp

## 1. Papel e objetivo

Atua como um engenheiro de software sénior especializado em Next.js, TypeScript, APIs, webhooks, integrações de e-commerce, automação de processos e segurança de aplicações SaaS.

Constrói uma aplicação web funcional que permita aos proprietários de lojas Shopify automatizar notificações de encomendas através do WhatsApp.

A aplicação deve permitir que cada utilizador conecte a sua loja Shopify, configure a sua instância da Evolution API, associe o seu próprio WhatsApp, defina o número do entregador e, opcionalmente, o número do proprietário da loja. Deve também disponibilizar um webhook copiável para integrar a Shopify com o sistema.

Não construas apenas um protótipo visual. Implementa o frontend, backend, base de dados, autenticação, integrações, tratamento de erros e documentação de instalação.

Se alguma integração depender de credenciais externas, implementa o fluxo real e apresenta instruções claras para configurar essas credenciais. Nunca simules uma conexão como se fosse real.

## 2. Stack tecnológica

Utiliza as seguintes tecnologias:

- Next.js com App Router.
- TypeScript em modo strict.
- React para a interface.
- Tailwind CSS para estilos.
- shadcn/ui para componentes da interface, se disponível.
- PostgreSQL como base de dados.
- Prisma ORM para o acesso à base de dados.
- Autenticação segura com Auth.js ou uma solução equivalente.
- Zod para validação de dados.
- API Routes ou Route Handlers do Next.js para o backend.
- Um sistema de jobs para processar notificações de forma assíncrona, preferencialmente BullMQ com Redis.
- Shopify Admin API e Shopify Webhooks.
- Evolution API para o envio de mensagens WhatsApp.
- n8n como integração opcional, permitindo que o utilizador escolha entre um fluxo processado diretamente pela aplicação ou um fluxo encaminhado para o seu n8n.

Utiliza versões estáveis e compatíveis das bibliotecas no momento da implementação. Consulta a documentação oficial antes de definir endpoints, autenticação ou estruturas de payload.

Não assumes que todas as funcionalidades estão disponíveis em todas as versões da Evolution API ou em todos os planos da Shopify.

## 3. Conceito do produto

A aplicação é uma plataforma de notificações de encomendas para lojas Shopify.

Quando um cliente cria uma encomenda, o sistema deve receber o evento da Shopify, validar os dados, identificar o número de WhatsApp do cliente e enviar as notificações configuradas.

O caso de utilização principal é o pagamento contra entrega.

A mensagem ao cliente deve confirmar que a encomenda foi recebida e informar o valor que deverá pagar ao receber o produto.

O sistema não pode afirmar que o pagamento já foi realizado.

O entregador deve receber uma notificação com os dados necessários para executar a entrega.

O proprietário da loja poderá ativar notificações adicionais sobre novas encomendas, falhas de envio ou outras ocorrências operacionais.

A moeda de apresentação deve suportar MZN, mas o sistema deve utilizar a moeda real recebida da Shopify.

Utiliza um design moderno, com navegação lateral no desktop e navegação adaptada ao telemóvel.

1. Telefone do endereço de entrega.
2. Telefone da encomenda.
3. Telefone do perfil do cliente.

Se não existir um telefone válido, a aplicação deve registar o problema e apresentar a encomenda para revisão manual.

Nunca inventes números nem envies mensagens para contactos inválidos.

Os números devem ser normalizados para formato internacional antes do envio, sem acrescentar indicativos duplicados.

Todos os números de destinatários devem ser configuráveis pelo utilizador e guardados na base de dados.

## 5. Arquitetura do processamento

Implementa o seguinte fluxo:

1. A Shopify cria uma encomenda.
2. A Shopify envia um webhook para a aplicação.
3. O backend verifica a assinatura HMAC sobre o corpo bruto da requisição.
4. O backend identifica a loja pelo webhook e valida o evento.
5. O evento é registado de forma idempotente.
6. A aplicação verifica se a encomenda está cancelada ou inválida.
7. A aplicação identifica o método e o estado do pagamento.
8. A aplicação obtém os dados do cliente, produtos, total e endereço.
9. O backend cria tarefas para cada destinatário aplicável.
10. O sistema envia as mensagens através da Evolution API.
11. O resultado de cada envio é registado individualmente.
12. O dashboard é atualizado com os resultados.

Não bloqueies o endpoint do webhook enquanto aguardas todos os envios. Valida o evento, regista-o e coloca o processamento numa fila de tarefas.

Responde à Shopify com um código HTTP apropriado após a receção e persistência segura do evento.

Se a persistência falhar, não confirmes o processamento como concluído.

## 6. Regras para pagamento contra entrega

A automação deve reconhecer que uma encomenda pode ser criada antes de existir pagamento.

Quando uma encomenda é recebida:

- Se estiver válida e não cancelada, pode gerar uma confirmação de receção.
- Se o método for contra entrega, a mensagem deve indicar o valor previsto para pagamento na entrega.
- Se o pagamento estiver pendente, não o classifiques como pago.
- Se estiver cancelada, não envies novas notificações normais de entrega.
- Se o método de pagamento não puder ser identificado, utiliza uma mensagem neutra e regista a situação.

Não assumes que todas as encomendas Shopify são contra entrega.

Implementa regras de cancelamento e, se possível, um evento para comunicar cancelamentos ao entregador quando a encomenda já tiver sido atribuída.

## 7. Segurança e isolamento entre lojas

A aplicação deve funcionar como uma plataforma multi-tenant.

Cada loja pertence a um utilizador ou organização.

Implementa:

- Autorização em todas as operações.
- Validação de dados no servidor.
- Proteção contra acesso a dados de outras lojas.
- Encriptação de credenciais sensíveis.
- Gestão segura de sessões.
- Rate limiting.
- Proteção contra SSRF na configuração da URL da Evolution API.
- Verificação de assinaturas de webhooks.
- Registos sem tokens ou API Keys.
- Segredos guardados apenas no backend.
- Proteção contra processamento repetido de webhooks.
- Política de retenção e eliminação de dados pessoais.
- Tratamento seguro de erros.

As credenciais da Shopify, Evolution API e n8n não podem ser expostas em componentes React, no armazenamento local do navegador ou em respostas públicas da API.

Se permitires URLs de servidores fornecidas pelo utilizador, bloqueia destinos internos e endereços de rede privada, com validação apropriada contra SSRF.

## 9. Integração com a Evolution API

Cria um módulo de serviço independente, por exemplo `lib/evolution/client.ts`.

Implementa funções equivalentes a:

- `checkConnection()`
- `createInstance()`
- `getQrCode()`
- `getConnectionState()`
- `sendTextMessage()`
- `configureWebhooks()`, se suportado pela versão utilizada.

Centraliza neste módulo todos os endpoints e detalhes específicos da Evolution API.

Não espalhes chamadas HTTP pela interface React.

Valida as respostas da API e converte erros do fornecedor em erros internos claros.

Implementa timeouts, retries limitados e tratamento de rate limits.

Não repitas automaticamente um envio se não for possível determinar se a primeira tentativa chegou a ser aceite. Nesse caso, utiliza um estado de resultado incerto e um procedimento de reconciliação para evitar mensagens duplicadas.

Se a Evolution API suportar webhooks de estado de mensagens, utiliza-os para atualizar os estados de entrega.

## 10. Integração opcional com n8n

A aplicação deve permitir dois modos de execução:

**Modo A: processamento direto**

Shopify → Backend Next.js → Fila de tarefas → Evolution API.

**Modo B: processamento via n8n**

Shopify → Endpoint seguro → n8n → Evolution API.

No modo B, o n8n pode comunicar com o backend para consultar as configurações e registar resultados, mas não deve receber segredos de outras lojas.

Cria uma configuração para o URL do n8n e uma opção para copiar o webhook correspondente.

Não tornes o n8n obrigatório para o funcionamento básico da aplicação.

Não permitas que o modo direto e o modo n8n processem simultaneamente o mesmo evento sem uma estratégia explícita de idempotência.

## 16. Critérios de conclusão

Considera a implementação concluída apenas quando:

- O utilizador consegue autenticar-se.
- Consegue conectar uma loja Shopify pelo fluxo oficial.
- Consegue configurar uma instância real da Evolution API.
- Consegue acompanhar o estado da conexão WhatsApp.
- Consegue configurar o seu número, o número do entregador e o número opcional do proprietário.
- Consegue copiar um URL de webhook válido.
- A Shopify consegue enviar um evento autenticado.
- O sistema processa a encomenda sem duplicação.
- As mensagens são enviadas aos destinatários corretos.
- Os erros são registados e apresentados no dashboard.
- Os segredos permanecem no backend.
- Os testes essenciais passam.
- A documentação permite instalar e executar o projeto.

Começa por analisar as versões atuais e a documentação oficial das APIs.

Depois, apresenta um plano curto de implementação, cria a estrutura do projeto e implementa as funcionalidades por etapas.

Não te limites a gerar pseudocódigo. Produz código funcional, executa os testes disponíveis e corrige os erros encontrados.

Se uma funcionalidade depender de uma configuração externa ainda não fornecida, implementa a integração real e identifica claramente o passo necessário para a ativar.

No final, apresenta um relatório com as funcionalidades concluídas, os testes executados, as configurações pendentes e as limitações conhecidas.
